# skill-lint

Проверка целостности скиллов [Claude Code](https://claude.com/claude-code): ловит битые ссылки,
сирот и раздутые `SKILL.md`. Без зависимостей — только стандартная библиотека Python.

## Зачем

Скилл грузится в два этапа: сперва `SKILL.md`, а справочники — по ссылкам из него.
Если ссылка битая, **никто не падает и не жалуется**. Агент просто молча пропускает шаг,
и заметить это можно только по тому, что работа сделана хуже обычного — без объяснения причин.

Особенно легко так сломаться при рефакторинге: вынес кусок в `references/`, переименовал файл,
переименовал скилл — и половина инструкций тихо перестала действовать. Скрипт превращает такую
тихую поломку в громкую.

## Что ловит

| | Проверка | Уровень |
|---|---|---|
| 1 | **Битая маршрутизация** — `SKILL.md` ссылается на `references/…`, которого нет | ⛔ ошибка |
| 2 | **Битые соседские ссылки** — внутри `references/` ссылаются коротко: `[текст](сосед.md)` | ⛔ ошибка |
| 3 | **Ссылка на несуществующий скилл** — `~/.claude/skills/<имя>/…` после переименования | ⛔ ошибка |
| 4 | **Сломанный frontmatter** — без `name`/`description` скилл не активируется вовсе | ⛔ ошибка |
| 5 | **Сироты** — файл в `references/` есть, но на него никто не ссылается | ⚠️ предупреждение |
| 6 | **Раздутый `SKILL.md`** — грузится целиком при каждой активации | ⚠️ предупреждение |

Проверки 1 и 2 разведены не для красоты: ссылки записываются в разных формах, и регулярка,
которая видит `references/foo.md`, не видит `[текст](сосед.md)` из соседнего файла.

Пути, ведущие в папку, которой у скилла нет вовсе (`assets/readme/hero.svg` у скилла без `assets/`),
считаются примерами, а не маршрутом — это предупреждение, а не ошибка. Иначе хук валился бы
на каждом скилле, который показывает примеры путей в чужом репозитории.

## Установка и запуск

```bash
python check_skills.py                       # все скиллы
python check_skills.py my-skill other-skill  # только эти
python check_skills.py --skills-dir ~/.claude/skills
python check_skills.py --quiet               # молчать, когда всё чисто
```

Папку скиллов скрипт ищет так: флаг `--skills-dir` → переменная `CLAUDE_SKILLS_DIR` → папка самого
скрипта, если в ней лежат скиллы → `~/.claude/skills`.

Пример вывода:

```
⛔ broken  (153 б)
     ⛔ во frontmatter нет `description:`
     ⛔ битая ссылка на соседа: nosuch.md (из references/lonely.md)
     ⛔ ссылка на несуществующий файл: references/missing.md
     ⛔ ссылка на несуществующий скилл: nosuchskill (в references/x.md)
     ⚠️  сирота (никто не ссылается): references/orphan.md
✅ good  (132 б)

скиллов: 3 · ошибок: 5
```

Коды выхода: `0` — чисто, `1` — есть ошибки. Предупреждения проверку не валят.

## Как повесить на хук

Полезнее всего запускать проверку автоматически — сразу после правки скилла, пока контекст ещё
свежий. В `~/.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python ~/.claude/skills/skill-lint/scripts/check_skills.py --hook",
            "timeout": 20,
            "statusMessage": "Проверяю скиллы"
          }
        ]
      }
    ]
  }
}
```

Две тонкости, на которых легко потерять день:

* **Режим `--hook` читает JSON со stdin и молчит, если правка была вне папки скиллов.** Без этого
  проверка шумела бы на каждом `Write`/`Edit` в любом проекте.
* **Код возврата в режиме хука — `2`, а не `1`.** Только двойку харнесс передаёт модели; с единицей
  сообщение осядет в логе, и его никто не прочитает.

## Настройка

`BUDGET` в начале файла — мягкий потолок размера `SKILL.md` в байтах (по умолчанию 15 000,
это примерно 5–6 тысяч токенов на каждую активацию). `SUBDIRS` — какие подпапки скилла считаются
его частью.
